# 🤖 Agentic Multi-Domain RAG System

A fully local, modular command-line application built on an **Agentic Retrieval-Augmented Generation (RAG)** architecture. The system dynamically routes user queries to specialized domain agents using a lightweight local LLM router.

Instead of maintaining multiple vector databases, the application uses a **single optimized Qdrant collection with metadata tagging**, ensuring both resource efficiency and retrieval precision.

The primary goal of the project is to demonstrate **multi-domain knowledge retrieval with intelligent agent routing**, while maintaining a **fully local, privacy-focused architecture** with zero dependency on paid cloud APIs.

### 🤖 Supported Agents (Knowledge Domains)

1. 🏎️ **F1 Expert** → Formula 1 history, drivers, rivalries, race statistics.
2. 🪐 **Space Explorer** → Astronomy, planets, astrophysics, and space science.
3. 🏙️ **Tricity Guide** → History, landmarks, and tourism of Gdańsk, Gdynia, and Sopot.
4. 🎬 **Film Critic** → Movies, cinema history, rankings, and recommendations.
5. 🌐 **General Assistant** → Fallback agent for general knowledge outside supported domains.

## 🛠️ Tech Stack & Architecture

This project follows an **Agentic RAG (Retrieval-Augmented Generation)** architecture, where a lightweight local LLM dynamically classifies the user's intent and routes queries to specialized agents.

Unlike traditional multi-database approaches, the system operates on a **single Qdrant collection** with **metadata-based domain filtering**, making retrieval efficient and scalable.

### 🧠 AI & Agent Layer

* **LLM Router & Specialist Agents:** `llama3.2` running locally via **Ollama**.
* **Agent Framework:** `agno` — used for multi-agent orchestration and intent routing.
* **Routing Strategy:** A dedicated **Root Router Agent** classifies the query into one of the following domains:
  * `f1`
  * `cosmos`
  * `tricity`
  * `film`
  * `other` (fallback → General Assistant)

The router dynamically dispatches the query to a specialized expert agent with domain-specific instructions.

### 🗂️ Vector Database & Retrieval

* **Vector Database:** `Qdrant` (Dockerized)
* **Collection Name:** `agents_knowledge`
* **Retrieval Strategy:** Semantic similarity search with metadata filtering.
* **Distance Metric:** `Cosine Similarity`

The project uses **one vector collection only**, instead of multiple databases. Each chunk receives a metadata label (`domain`) and retrieval happens only inside the selected category.

Example filtering logic:

```python
FieldCondition(
    key="domain",
    match=MatchValue(value=domain)
)
````

### 🔎 Embeddings & Chunking

* **Embedding Model:** `sentence-transformers/all-MiniLM-L6-v2`
* **Vector Size:** `384`
* **Chunk Size:** `900`
* **Chunk Overlap:** `120`
* **Top-K Retrieval:** `3`

Document chunking is performed using:

* `LangChain` → `RecursiveCharacterTextSplitter`

Configuration:

```python
CHUNK_SIZE = 900
CHUNK_OVERLAP = 120
TOP_K = 3
```

### 📄 Document Processing (ETL Pipeline)

PDF documents are processed locally using:

* **PyMuPDF (`fitz`)** → PDF text extraction
* **UUID-based chunk indexing**
* **Automatic domain detection via filename rules**

Example domain mapping:

```python
DOMAIN_RULES = [
    ("f1", ["Prost", "Senna", "Hamilton", "Schumacher"]),
    ("cosmos", ["jupiter", "mars", "saturn"]),
    ("tricity", ["Gdansk", "Gdynia", "Sopot"]),
    ("film", ["film"]),
]
```

### 🖥️ User Interface

* **CLI Interface:** `Rich`
* Terminal progress bars
* Colored logs
* Upload tracking
* Interactive terminal output

### 🔓 Why This Architecture?

This project was intentionally designed as a **fully local multi-agent RAG system**.

Advantages:

* **100% Local Execution** — no cloud APIs
* **Privacy First** — documents never leave the machine
* **Zero API Cost** — no token billing
* **Efficient Retrieval** — one Qdrant collection with filtering
* **Dynamic Expert Routing** — specialized agents per domain
* **Hallucination Reduction** — agents are instructed to answer only from retrieved context

## 🚀 Setup & Installation (WSL / Linux)

Follow these steps to recreate the project locally.

### Step 1: Create Virtual Environment

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Step 2: Install Dependencies

```bash
pip install agno qdrant-client sentence-transformers langchain-text-splitters pymupdf rich ollama
```

### Step 3: Start Qdrant Database

```bash
docker-compose up -d
```

### Step 4: Add Your PDFs

Create the folder:

```bash
mkdir -p data/pdfs
```

Add your PDF knowledge base files inside:

```text
data/pdfs/
```

### Step 5: Run Ingestion Pipeline

Generate embeddings and upload vectors to Qdrant:

```bash
python src/ingest.py
```

### Step 6: Launch the System

```bash
python src/cli.py
```
